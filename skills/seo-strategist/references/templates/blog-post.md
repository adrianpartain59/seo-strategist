# Template: blog post (Month 1 cluster and Month 2 refreshes)

Long-tail questions under a pillar ("<brand> rash", "time blocking with ADHD",
"<thing> after <event>"). Plan Type: `Blog`. Same plan format and copy rules as
the pillar guide, shorter: 7–8 sections, ~22–28 H3s, ~900–1,200 words.

## Post layout (what the blog template should render)

Breadcrumb (Brand / Guides / <Topic>) · H1 · **SHORT ANSWER** callout right
under the H1 (2–4 sentences that answer the query completely) · an honest
disclosure line where the brand has a stake ("We make <Brand>, so we are not
neutral. Every fact below comes from <sources>, checked on <date>.") · "On this
page" numbered table of contents with nested H3s · body · FAQ · sources.
Rails: sticky table of contents and a product CTA card on the left, a
newsletter sign-up on the right. If the site's blog lacks these, list them in
the plan's first Key Components so the developer adds them once.

## Section order

| # | Section | H3s |
|---|---|---|
| 1 | H1 + short answer callout | 1 |
| 2 | Is it normal / what it is (sourced facts with numbers) | 3–4 |
| 3 | What it looks like / when it happens / how long it lasts | 3–4 |
| 4 | What the source says to do, and what it leaves to the professional | 3–4 |
| 5 | When to get help / when to escalate | 3–4 |
| 6 | How to track it in the product (links to the money page named in blog.csv) | 3 |
| 7 | Related reading: the pillar + 2 sibling posts | 2–3 |
| 8 | FAQ (5–7) | 5–7 |

Title leads with the term people search (brand name over generic when people
search the brand). Every post links up to its pillar and across to one money
page.

## Month 2 refresh

An existing article rewritten "to the current standard": short answer at the
top, FAQ, cited sources, a comparison table where it fits, current meta.
Use the existing-page template (diff), keep the slug.
